# Как проверить требования ТЗ

На демостенде у клиента два филиала, у администратора доступны обе компании. Сначала войдите под клиентом, затем повторите выбор филиала под администратором. Обе учётные записи приведены в инструкции. [Условия задания](../TASK.md) · [Запуск и демологины](../README.md#запуск)

| Раздел | Что проверить | Реализация и тесты |
| --- | --- | --- |
| Вход и роли | После входа клиент видит свои филиалы. Прямая ссылка на филиал другой компании возвращает 404. | [Область доступа](../apps/api/src/common/access-scope.ts) · [Интеграционные тесты ролей](../scripts/tenant-permissions.test.js) |
| Дашборд | Измените период и показатель. Карточки, график и экспорт показывают данные одного диапазона. | [Запрос отчёта](../apps/api/src/modules/metrics/metrics.repository.ts) · [Дашборд в Chromium](../e2e/cabinet.spec.js) · [CSV](../e2e/export.spec.js) |
| Филиалы | Откройте таблицу, отсортируйте по просмотрам и перейдите в филиал. Выберите второй филиал для сравнения. | [Таблица](../e2e/branch-table.spec.js) · [Сравнение](../e2e/comparison.spec.js) |
| API и PostgreSQL | При первом запуске применяются миграции. Сид создаёт две компании, четыре филиала и двух пользователей с разными ролями. | [Схема](../prisma/schema.prisma) · [Миграции](../prisma/migrations) · [Демоданные](../prisma/seed.js) |
| Вариант А. Отзывы | Выберите рейтинг и статус, перейдите на следующую страницу. Измените статус и обновите страницу. | [Модуль отзывов](../apps/api/src/modules/reviews) · [Браузерный тест](../e2e/reviews.spec.js) |
| Вариант Б. Импорт | Войдите администратором и дважды импортируйте один период. В базе остаётся одна строка на филиал и дату. | [Модуль импорта](../apps/api/src/modules/imports) · [Проверка через HTTP и PostgreSQL](../scripts/smoke.js) |

Команда `make check` запускает тесты приложения. На работающем стенде `make smoke` сверяет результат импорта с PostgreSQL. [Скриншоты](screenshots/README.md) · [Архитектурные решения](../DECISIONS.md)
